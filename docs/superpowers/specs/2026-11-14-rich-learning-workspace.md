# Rich learning workspace revision

The user approved source publication, then reported that the deployed guide looked
sparse and unfinished. The first version overemphasized a large heading and one
installation exercise, hiding the product's breadth and actual outputs. A high
rubric score did not establish that this was a useful or convincing first screen.

## Revision

Keep the deployed Web Function, Cognito and Haiku/Luna backend. Rebuild the React
home as a compact learning application with a persistent plugin navigator,
searchable workflow catalog, real example previews and actionable exercises.
The first desktop viewport must contain recognizable outputs and several useful
entry points. Mobile must show useful content before a long plugin menu.

Every catalog entry has a concrete request, expected output, verification and a
valid bilingual reference. The user selects a workflow and learns it inside the
React interface, rather than being sent immediately to a long reference page.
Installation remains available as a compact prerequisite. Host-specific dashboard
limitations must remain precise. Published examples are labeled as examples.

Use maintained screenshots and frozen demos; do not invent screenshots, live
metrics, user activity or status. Include a focused preview dialog with accessible
close behavior and a full-size link. Search and plugin selection need clear empty
states and shareable URLs. Preserve both locales and contextual chatbot behavior.

## Validation and delivery

Verify catalog membership, source links and assets; typecheck; validate locale
coverage; build both locales; inspect 1440px and 390px layouts and actual user
actions. Content review >=85 remains required, but assess content visibility and
usefulness explicitly in addition to the existing rubric. Deploy a new immutable
Web Function revision and verify the public site. Push the approved source and
create a PR covering the final implementation.
