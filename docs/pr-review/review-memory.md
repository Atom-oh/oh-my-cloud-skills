**A single file** that both CI review (`.github/workflows/pr-review.yml`) and the interactive
review agents read together. `memory_excerpt` (`scripts/pr-review/lib.sh`) inlines an excerpt
into the lens prompt, and the chair `Read`s this path directly. Because `pull_request_target`
checks out the base ref, an update only takes effect starting with the **next** PR merged into
`main` (the same delay characteristic as a roster change).

Cap each section at the most recent 30 lines — delete stale entries, and **delete wrong entries
immediately**. Keep the whole file under 200 lines.

## Recurring real issues (must not recur)
- `grep -c` prints `0` on zero matches but exits 1, so appending `|| echo 0` produces `"0\n0"` — use `|| true` instead (source: PR #140)
- Copying an existing doc claim into a new section without re-checking it against the script's actual behavior propagates stale claims — "`test-codex-plugins.py` reports project-init absence as a warning" was false (deliberate silent skip, `CLAUDE_ONLY`) (source: PR #158; the original claim predates it)
- Refactoring a counter/state onto a file drops two things together: (a) the initialization write itself and (b) the fail-hard (`|| exit 1`) the old path had — check the diff for both whenever an existing fail-hard is deleted (source: PR #158, kiro-opus + kiro-gpt convergent)
- Introducing a terminal phase into a per-PR persistent state file without a reset/re-init path silently voids init-only-resolved config (`max_iter`) on re-runs after a stop — a state-file diff must answer "how do you leave the terminal state" (source: PR #158 round 2, 3-cell convergent)
- Restating AWS security mandates in a skill/doc body drifts from the authoritative `AGENTS.md` §Banned patterns (rules get weakened, dropped, or over-extended). Point at `AGENTS.md` instead of paraphrasing it, or diff any restatement against it verbatim before landing — this recurred within the same PR one round later (a fix-round edit re-added an over-extension, "or API", not present in the source) (source: PR #156 round 1 + round 2; the same wording drift was already present in `docs/reference/review-routing.md`).
- A "ALL state lives in ONE file" declaration must be checked against every resume path, not just the happy path — if mid-pass resume (e.g. a committed-but-not-pushed gate re-entry) still needs an external handle (a run directory, a notes-only signature) the declaration is false on its own terms. When promoting ad hoc counters into a state file, record every handle a resume path needs inside that same file (source: PR #158 round 3, codex + kiro-opus convergent; recurred unfixed into round 4, fixed in round 4 by adding `run_dir`/`sig` to the schema).
- When a skill introduces a flat, unconditional security mandate table, check whether the SAME skill's own `references/*.md` files already grade that mandate by severity/exception (e.g. a "banned pattern" table landing next to a reference file that scores the same pattern HIGH/MEDIUM/CRITICAL by port, or expects a stricter/looser condition) — the two can silently contradict inside one skill tree even when each is individually correct against its own source (source: PR #156 round 3: `ops-security-audit/SKILL.md`'s new mandate table vs. `references/network-security.md` and `references/iam-audit.md`).
- A state-file init written as `cmd > "$FILE" || exit 1` guarded by existence-only (`[ ! -f "$FILE" ]`) is not fail-hard: shell redirection truncates/creates the file BEFORE `cmd` runs, so a failed init (e.g. an upstream config call returning empty) leaves a zero-byte file that the next entry's existence check treats as already-initialized. From there, reads of missing keys return empty, and bash bound checks like `[ "" -ge "" ]` error-evaluate to false — silently disabling the loop's only bound. Fix: write to `$FILE.tmp` then `mv`, and guard on content validity (e.g. `jq -e 'has(...)'`), not mere existence (source: PR #158 round 4, kiro-opus).
- A "the gate has no third verdict" (or similar exhaustive verdict-classification) claim must be diffed against the script's actual full set of terminal outputs, not just the framework it's describing — `consensus_hooks.py`'s pre-push-gate has a pre-lens secret-scan BLOCK that is neither a lens-count verdict nor covered by a 2-outcome lens framework (source: PR #158 round 4, codex).
- A persistent phase enum needs one value per resumable point, not per named step — if a single phase value's write-to-write window spans multiple side-effectful stages (e.g. commit → gate → push → cleanup → a follow-up commit+push), the resume contract for that value is false for every stage after the first. For each phase value, check whether re-entering AT that value is safe given everything the code actually does before the NEXT phase write, not just what the node's name suggests (source: PR #158 round 5, codex + kiro-gpt + kiro-opus 3-cell convergent).
- When persisting "every handle a resume path needs" into a state file, script-hash/setup-time-value handles (e.g. a `--script-sha` a downstream tool's own tamper-check requires) count too, not just path/signature handles — the round-3 fix covered `$RUN`/`$SIG` and missed `$LD_SHA`, even though the downstream tool's own self-check explicitly requires the CALLER to supply the original setup-time hash rather than a fresh re-hash (source: PR #158 round 6, codex confirmed against `land_delta.sh`'s `_verify_self`).
- A phase written BEFORE the side-effecting command it names (e.g. a `"committing"` phase set immediately before calling the actual commit) creates a genuine "did this actually happen yet" ambiguity on resume — don't assume it always means "already succeeded". Disambiguate with an observable fact (e.g. compare a git-derived count before vs. after) and branch the resume logic on it explicitly (source: PR #158 round 6, kiro-opus + codex convergent on the phase-granularity axis).
- A state write that increments/transitions based on an external side-effecting command's success (e.g. writing `phase: "gate"` right after `land_delta.sh commit`) needs its OWN fail-hard guard on that command's exit status — "every state write fails hard" as a blanket claim covers the jq write mechanics only, not whether the fact the write asserts (the commit happened) is actually true (source: PR #158 round 6, kiro-gpt).
- When a fix adds a fail-hard/self-check guard to ONE side-effecting command a review flagged, enumerate every OTHER side-effecting-command → state-write pair in the SAME file before declaring the rule satisfied — round 6 added `|| exit 1` to `land_delta.sh commit` but left the very next `push`/`cleanup` calls unguarded, so a failed push still advanced `phase` to `poll` and deleted the worktree (source: PR #158 round 7, 3-cell convergent).
- An unconditional entry-block repair (e.g. adopting a git-derived count into a stored field on every single invocation, with no phase guard) can silently shadow a LATER phase-specific resume check that wants to compare the stored value against the same git-derived fact — by the time the later check runs, the repair has already overwritten the value it needed to read, making that branch permanently dead code. Verify a "read before the check below adopts a new value" claim by tracing actual execution order, not document order (source: PR #158 round 7, 3-cell convergent).
- A written recovery instruction for a human ("go complete X in location Y") must be checked against where the pipeline ACTUALLY performs that operation, not assumed from a variable's name — `land_delta.sh` commits on the HOST tree, while `$RUN` is a `--detach`ed worktree used only to capture an implementer's edits before landing; a "commit in `$RUN`" instruction sends a human to make an orphaned commit that never reaches the PR branch (source: PR #158 round 7, codex confirmed against `land_delta.sh` setup/cmd_commit).

## Known false-positive patterns (do not flag again without evidence)
- L3: `AKIA…`/`sk-proj-…` strings in fixtures under `tests/` are intentional fake values used to test the scrubber itself — not hardcoded secrets (source: PR #141)
- L4: `head -c "$cap" "$file"` (file argument) carries no SIGPIPE risk — only the piped form (`… | head -c`) dies with 141 (source: PR #141)
- A `{plugin-dir}/path.md → *Section*` pointer flagged as dangling because the target isn't visible in the diff — the target section frequently already exists in the base file untouched by the diff. Grep the actual repo for the target heading before flagging (source: PR #156 — two kiro-opus MAJOR findings dismissed on this exact basis).
- An agent's goal-statement prose ("delivers the fix") and its own *Team Collaboration* section ("leave the fix to the coordinator") are not a conflict — they describe the solo-mode default vs. the `team_name`-set override, and the team section explicitly states it overrides. Don't flag this pairing as "conflicting execution authority" without checking whether the agent has both a solo path and a team path (source: PR #156, kiro-gpt).
- The co-agent pre-push lens gate has exactly two BLOCK verdicts *among lens verdicts*: 2+ lenses = hard BLOCKED, exactly 1 lens (any lens) = CHAIR JUDGMENT REQUIRED (`consensus_hooks.py`) — "CHAIR" is verdict framing, not a lens name, so "the 1-non-chair-lens case is undefined" edge-gap findings are baseless. Note the caveat: the gate ALSO has a pre-lens secret-scan BLOCK outside this 2-verdict lens framework entirely — see the round-4 recurring-issue entry above (source: PR #158, kiro-gpt; refined PR #158 round 4).
- In a prose SKILL.md, an explicit instruction ("resuming … → honor it as `true`") IS the spec — don't raise "unspecified" to MAJOR just because no shell command accompanies it; the asymmetry is at most MINOR when the skill shows commands for its other transitions (source: PR #158).
- The panel-quality table only updates rows for cells that had unsupported findings that round (the chair emits PANEL-QUALITY only for those cells) — a row sitting at an older PR next to same-PR real-issue credit is correct, not "inconsistent" (source: PR #158 round 2, kiro-opus).
- A finding that a gitignored, untracked, host-computed local state file (e.g. `.claude/co-agent-consensus/**`) could be "pre-seeded" or symlink-attacked by a malicious PR requires the attacker to already have local working-tree write access — at which point the finding restates its own precondition rather than identifying a new threat. Check whether the attack actually needs pre-existing local compromise before raising it (source: PR #158 round 3, codex CRITICAL dismissed).
- **Reverse case of the "mandate drifts from AGENTS.md" issue above**: a fix that CORRECTS an existing drift (e.g. tightens `Principal:"*"` to match `AGENTS.md`'s unconditional ban, after older text wrongly allowed a Condition exception) can get flagged as itself being an "over-extension" by a panel cell comparing only against the diff's old text, not against `AGENTS.md`. Always diff the claimed source of truth directly — a correction is not a violation (source: PR #156 round 3, two cells).
- "A blocked-but-unpushed commit is never re-reviewed" is false for the co-agent pre-push gate specifically — it reviews the push RANGE, so an unpushed commit is automatically back in scope on the next gate invocation. Check the gate's actual diff range before flagging a non-durability concern (source: PR #158 round 4, kiro-opus MAJOR downgraded to MINOR).
- "A committed secret can't be removed via a re-plan follow-up because the gate reviews the push range" is false for `consensus_hooks.py`'s secret scan specifically — it scans the ADDED lines of the range's net diff (`base...HEAD`), so a follow-up commit that deletes the offending line removes it from that net diff and the scan passes; removal-only hits are advisory (`hard=False`) by the scanner's own design, never a hard block. Check what the scanner actually diffs before flagging a re-plan attempt as wasted (source: PR #158 round 5, kiro-opus dismissed).
- "An implementer could write/corrupt the host state file via an absolute path" restates the round-3 dismissed pattern (a gitignored, untracked, local state file's threat model already presumes local write access) rather than identifying a new trust boundary the diff introduces — check for an actual NEW boundary before re-raising this shape of finding (source: PR #158 round 6, codex re-dismissed).
- A reference doc's example snippet hardcoding only rung 1 of a multi-rung table is not itself a MAJOR gap if the table + a "(or the resolved rung)"-style comment sit directly above it — that's a prose-is-spec instruction, not missing logic, and doesn't need the snippet to literally compute every rung (source: PR #158 round 7, kiro-gpt dismissed; variant of the "prose SKILL.md explicit instruction IS the spec" pattern).
