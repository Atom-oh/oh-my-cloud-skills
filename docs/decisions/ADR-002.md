# ADR-002: Image-based PPTX export via html2canvas

## Status

Accepted

## Context

The original PPTX export used DOM text extraction (`querySelector` for headings, lists, code) and `addText()` calls. This produced text-only slides that lost all visual layout, icons, canvas animations, and CSS styling. Interactive elements (canvas, Mermaid) were replaced with `[Interactive]` placeholders.

## Options Considered

1. **Enhanced text extraction** — Parse more DOM elements, approximate layout with absolute positioning. Still loses CSS, gradients, icons.
2. **Server-side rendering** — Use Puppeteer/Playwright to screenshot slides. Requires Node.js server, not client-side.
3. **Client-side iframe + html2canvas** — Load each block HTML in a hidden iframe (1920×1080), complete all animations, capture with html2canvas, insert as image into PPTX.

## Decision

Adopted option 3. Each block is loaded in a hidden same-origin iframe. `_completeAllAnimations()` reveals all fragments and advances canvas steps to final state. `html2canvas` captures each slide as PNG. `PptxGenJS.addImage()` inserts the image full-bleed. Heading text is added as slide notes for searchability. Text fallback exists for capture failures.

## Consequences

- PPTX slides preserve full visual fidelity (layout, icons, charts, animations in final state)
- File size is larger (PNG images vs text)
- Slides are not editable in PowerPoint (image-based)
- Requires CDN access for html2canvas library
- Cross-origin iframes would break; only works with same-origin block files
