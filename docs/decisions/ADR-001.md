# ADR-001: Stack-based block parser replacing regex

## Status

Accepted

## Context

The original Remarp markdown parser used regex patterns to match `:::` block delimiters. This broke on nested blocks (e.g., `:::html` inside `:::columns`) because regex cannot reliably track nesting depth. Pandoc-style colon-count nesting (`::::` vs `:::`) was added but regex still failed on complex cases.

## Options Considered

1. **Enhanced regex** — More complex patterns with lookahead/lookback. Fragile, hard to maintain.
2. **Stack-based parser** — Track nesting via a stack of `ParsedBlock` objects. Each `:::` opener pushes, closer pops. Inner blocks processed before outer ones.

## Decision

Adopted stack-based parser (`parse_all_blocks_stack()` in `remarp_to_slides.py`) with `ParsedBlock` dataclass. The parser counts colons to determine nesting level and processes blocks inside-out.

## Consequences

- Nested `:::html` inside `:::columns` works correctly
- Pandoc-style colon-count nesting (`::::` for outer, `:::` for inner) is properly handled
- Parser is more maintainable but requires understanding the stack model
- `parse_columns()` must run after inner blocks are resolved
