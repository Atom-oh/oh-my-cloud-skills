## Codex 프롬프트

Codex에서는 Claude plugin을 그대로 실행한다기보다, Codex plugin으로 노출된 skill instruction을 사용해 Remarp 소스를 만들고 build CLI를 실행하는 흐름이 가장 안정적입니다.

```text
$aws-content-plugin reactive-presentation 을 활용해서 Amazon Bedrock에 대한 슬라이드를 만들어줘.

요구사항:
- 결과물은 docs/static/demos/bedrock-presentation 에 배치
- 한국어로 작성
- 대상은 클라우드 엔지니어, 개발자, 솔루션 아키텍트
- 수준은 200-300
- 30분 발표 분량
- 복잡한 아키텍처 슬라이드는 Canvas 좌표 기반보다 :::html + :::css 레이아웃으로 만들어줘
- 모든 슬라이드에 speaker notes 포함
- validate와 build까지 실행
```

## 생성된 파일

```text
docs/static/demos/bedrock-presentation/
├── _presentation.md
├── 01-bedrock-overview.md
├── index.html
├── bedrock-overview.html
└── common/
    ├── theme.css
    ├── slide-framework.js
    └── aws-icons/
```

## 검증과 빌드

Remarp 소스를 수정한 뒤에는 먼저 validation을 실행하고, critical issue가 없을 때 HTML을 빌드합니다.

```bash
python3 plugins/aws-content-plugin/skills/reactive-presentation/scripts/remarp_to_slides.py validate docs/static/demos/bedrock-presentation
python3 plugins/aws-content-plugin/skills/reactive-presentation/scripts/remarp_to_slides.py build docs/static/demos/bedrock-presentation
```

## 구성 포인트

| 슬라이드 | 설계 의도 |
|----------|-----------|
| Cover | Bedrock 발표의 대상, 난이도, 시간을 첫 화면에서 명확히 표시 |
| Why Bedrock | 모델 선택, 엔터프라이즈 운영, 프로덕션 연결성을 3개 카드로 요약 |
| Mental Model | 모델, 데이터, 도구, 안전장치, 운영을 한눈에 보는 구조 |
| Reference Architecture | Experience, Application, Bedrock, Data/Ops 계층을 분리한 아키텍처 다이어그램 |
| RAG / Agents / Guardrails | 실제 도입 시 가장 많이 묻는 기능을 별도 슬라이드로 분리 |
| Adoption Pattern | Pilot에서 운영까지의 진행 단계를 타임라인으로 표현 |

## 다이어그램 작성 기준

Bedrock처럼 요소가 많은 아키텍처는 Canvas 좌표를 직접 찍는 방식보다 `:::html`과 `:::css`를 사용하는 편이 안정적입니다. Flexbox와 Grid가 간격, 정렬, 반응형 크기를 관리하기 때문에 PPT 수준의 도식 품질을 만들기 쉽고, 각 박스에 fragment animation을 넣어 발표 중 단계적으로 설명할 수 있습니다.
