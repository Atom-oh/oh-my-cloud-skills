# v2.0.0 릴리스 및 마이그레이션

**2026-09-13**에 출시했습니다. Claude Code와 Codex용 플러그인 8개 모두
버전 **2.0.0**을 공유합니다. 이번 메이저 릴리스에서는 co-agent의 지원 대상에서 Antigravity를 제외합니다.

[태그된 소스](https://github.com/Atom-oh/oh-my-cloud-skills/tree/v2.0.0) ·
[전체 변경 기록](https://github.com/Atom-oh/oh-my-cloud-skills/blob/v2.0.0/CHANGELOG.md)

## 변경 사항 {#what-changed}

- **플러그인 8개 모두 Codex 패키지를 제공합니다.** 생성된 항목으로 공유 워크플로를
  제공하며, 훅 실행에는 여전히 호스트 지원과 신뢰 설정이 필요합니다.
- **Co-agent는 Kiro와 반대편 호스트 CLI를 사용합니다.** Antigravity(`agy`)와
  기존 Gemini CLI는 지원이 종료되었습니다. 명시적인 호스트 구현에는 최신 상태로
  준비된 외부 검토자가 필요합니다.
- **문서는 공유 영문 소스를 사용합니다.** 번역 가이드는 로케일 경로를 유지하고
  기능 호출 별칭도 계속 사용할 수 있습니다. 고정된 데모는 원래 결과를 유지합니다.
- **저장소 검토 자동화는 현재 PR을 검증합니다.** 미해결 Critical/Major 발견 사항은
  병합을 차단하고 검토 범위 누락은 오류이며, 오래된 결과로 최신 검토를 대체할 수 없습니다.
  Kiro 검토 사전 점검은 도구 권한이 없는 에이전트를 검증합니다.

## 설치 업데이트 {#update-your-installation}

마켓플레이스를 새로 고치고 호스트의 플러그인 관리자를 통해 사용하는 플러그인을
업데이트합니다. 새 세션이나 스레드를 시작해 갱신된 패키지를 불러옵니다.
호스트별 설치 방법은 [시작하기](/docs/intro#install)를 따릅니다.

co-agent는 설정 절차나 구현 워크플로를 실행하기 전에 실제 적용 설정을 확인합니다.
설치만으로 외부 AI 인증, 모델 가용성, 훅 신뢰가
확립되지는 않습니다.

## Co-agent 마이그레이션 {#co-agent-migration}

1. `/co-agent:configure`를 열어 표시된 설정 출처를 확인합니다.
   지원이 종료된 외부 AI 설정을 해당 사용자 또는 프로젝트 재정의에서 제거합니다.
   여기에는 `panel`, `harness.implementer_models`, `harness.implementer_efforts`의
   지원 종료 항목과 해당 `harness.implementer` 선택이 포함됩니다.
   지원되는 외부 AI의 설정은 유지합니다.
2. 지원되는 외부 AI와 해당 제공자의 모델 설정을 선택합니다. 지원이 종료된
   제공자의 모델 이름이 다른 CLI에서도 자동으로 유효한 것은 아닙니다.
3. 오케스트레이션 프로젝트에서 `/co-agent:setup`을 실행해 준비 상태를 갱신합니다.
   게이트가 있는 작업 전에 인증, 모델 호출, 설정 오류를 해결합니다.
4. 아래에 설명된 구현 모드를 선택합니다. 작업이 별도 작업 트리로 이동해도
   설정과 준비 상태 조회는 설정 절차를 실행한 프로젝트를 기준으로 유지합니다.

Codex에서는 대응하는 설치된 스킬 항목을 선택합니다. 위 슬래시 명령은
공유 워크플로의 이름입니다. 정확한 설정과 도우미 명령은
[v2.0.0 설정 가이드](https://github.com/Atom-oh/oh-my-cloud-skills/blob/v2.0.0/plugins/co-agent/commands/configure.md)를
기준으로 합니다.

## 외부 AI 및 구현 모드 {#peers-and-implementation-modes}

| 현재 호스트 | 외부 검토 후보 | 적격 외부 harness 구현자 |
| --- | --- | --- |
| Claude Code | Kiro CLI와 Codex CLI | 활성화되어 있고 READY 상태인 Codex |
| Codex | Kiro CLI와 Claude CLI | 없음 |

현재 호스트는 항상 외부 AI 호출 대상에서 제외합니다. 실제 참여 여부는
설정과 준비 상태 점검 결과에 따라 달라집니다.

Harness는 자격을 갖춘 READY 구현자가 있으면 선택합니다. 사용할 수 있는 구현자가
없으면 `--allow-host-implementation`으로 승인된 호스트 구현 계획을 명시적으로
선택해야 합니다. 이때 계획 도우미의 JSON은 `mode: host`를 표시하고
외부 구현자는 null로 지정합니다. 추가 쓰기 권한을 부여하는 것은 아닙니다.

두 모드 모두 활성화되어 있고 최신 READY 상태인 raw CLI 검토자가 필요합니다.
잘못된 설정이나 준비 상태는 계획을 중단시키며 대체 구현을 승인하지 않습니다. 호스트 구현도
작업 트리, 범위가 제한된 변경 캡처, 테스트, 외부 검토 게이트를 유지합니다.
[harness 가이드](/docs/co-agent/usage-guide#choose-an-implementation-workflow)에서
전체 절차를 확인할 수 있습니다.

## 검토 및 사용 경계 {#review-and-usage-boundaries}

review, decide, ADR 모드는 명확히 안내한 뒤 단독 진행할 수 있습니다. Consensus와
harness는 필수 외부 검토를 유지합니다. 선택적 로컬 PR·푸시 훅은
저장소 CI 및 브랜치 보호와 별개입니다.

계정 한도 오류가 발생하면 필수 CI 검토는 미완료 상태로 남습니다. 병합 전에
제공자 오류를 해결하고 실패한 검토를 다시 실행합니다.
