# 전달받은 슬라이드로 발표하기

다른 사람이 만든 reactive-presentation 슬라이드로 발표할 때 보는 안내입니다. **덱**(deck)은 발표에 쓰는 슬라이드 묶음입니다. 배포된 덱은 브라우저에서 발표할 수 있으므로 Claude Code, Codex, 플러그인을 설치하거나 Markdown 문법을 배울 필요가 없습니다.

**처음이라면 [발표 시작하기](#start-your-presentation)를 따라 하고, [상호작용](#operate-interactive-slides)을 연습한 뒤 [문제 해결 표](#recover-during-a-talk)를 곁에 두세요.** 작성자는 발표 링크와 함께 [인수인계 양식](#author-handoff)을 채운 슬라이드별 진행표를 전달하면 됩니다.

이 안내는 현재 기본 조작을 설명합니다. 덱마다 키와 상호작용을 바꿀 수 있고, 예전에 만든 덱에는 당시 버전이 남아 있습니다. 동작이 다르면 작성자가 해당 덱에서 확인한 안내를 우선합니다.

## 작성자에게 받아 둘 것 {#what-you-need}

| 받을 것 | 필요한 이유 |
| --- | --- |
| 발표 링크와 시작할 슬라이드 또는 세션 | 맞는 자료를 예정한 위치에서 시작하기 위해서입니다 |
| 청중, 발표 시간, 전달할 핵심 내용 | 배경 설명을 얼마나 하고 어디에 시간을 쓸지 알 수 있습니다 |
| 발표자 노트와 슬라이드별 진행표 | 각 장에서 할 설명, 조작 순서, 퀴즈 정답, 다음 장으로 연결할 말을 확인합니다 |
| 검증한 데스크톱 브라우저와 변경한 단축키 | 작성자가 확인한 환경에서 리허설할 수 있습니다 |
| 인터넷이 필요한 데모와 대체 설명 | 연결이나 라이브 데모에 문제가 있어도 설명을 이어갑니다 |
| 확인을 마친 PDF 또는 PowerPoint 사본 | 인터랙티브 덱을 사용할 수 없을 때 정적인 자료로 마무리합니다 |

바로 열 수 있는 발표 링크를 받는 것이 편합니다. ZIP을 받았다면 전체 폴더를 압축 해제하고 작성자가 확인한 열기 방법을 따르세요. 함께 제공된 **common/**, **assets/**, **archify/** 폴더를 HTML과 함께 유지합니다. HTML 파일 하나만 옮기면 스타일, 이미지, 다이어그램이 빠질 수 있습니다. 열기 방법이 없다면 바로 접속할 수 있는 링크를 요청하세요.

보통 **index.html**은 본 발표이고, **toc.html**은 발표 블록을 선택하는 세션 목차입니다. 모든 덱이 이 파일명을 쓰는 것은 아니므로 전달받은 발표 링크를 사용하세요.

## 발표 시작하기 {#start-your-presentation}

### 1. 슬라이드를 열고 한 번 넘겨 보기 {#open-the-slides}

1. 작성자가 검증한 데스크톱 브라우저에서 받은 링크를 엽니다.
2. 세션 목차가 나오면 발표할 세션을 선택합니다.
3. 슬라이드의 빈 공간을 클릭해 키보드 입력이 발표 화면으로 가게 합니다.
4. **오른쪽**을 한 번, **왼쪽**을 한 번 누릅니다. 슬라이드 번호는 그대로인데 글머리표만 나타나거나 사라질 수 있습니다. 설명을 단계별로 보여 주는 정상 동작입니다.
5. 청중 화면에 연결하기 전에 글자, 이미지, 다이어그램이 잘 보이는지 확인합니다.

휴대폰이나 태블릿으로 연습한다면 터치 조작을 따로 확인하세요. 아래의 두 창 구성은 데스크톱 브라우저 기준입니다.

### 2. 나만 볼 발표자 창 열기 {#open-presenter-window}

슬라이드 창에서 **N**을 누릅니다. 현재 슬라이드, 다음 슬라이드, 발표자 노트, 경과 시간을 보여 주는 **Presenter View** 창이 따로 열립니다. 아무 창도 열리지 않으면 해당 발표 사이트의 팝업을 허용하고 N을 다시 누릅니다.

처음 연 슬라이드 창은 닫지 마세요. 발표자 창이 그 창에 연결되어 있습니다. 발표 링크를 새 탭에 한 번 더 여는 것은 N으로 여는 발표자 창과 다릅니다.

*두 번째 창은 발표자용입니다. 본인 화면에 두세요.*

### 3. 청중에게 보여 줄 창 선택하기 {#choose-the-shared-window}

| 발표 환경 | 청중에게 보여 줄 것 | 내가 볼 것 |
| --- | --- | --- |
| 프로젝터 또는 두 번째 모니터 | 청중용 디스플레이에 놓은 원래 슬라이드 창 | 노트북의 Presenter View |
| 화상 회의 | 원래 슬라이드 창 또는 그 브라우저 탭만 공유 | 별도로 열어 공유하지 않는 Presenter View |
| 화면 하나라서 개인용 창을 둘 공간이 없음 | 원래 슬라이드 창 | 필요한 경우 따로 준비한 발표 메모 |

물리적 화면을 두 개 쓴다면 **디스플레이 확장**을 선택해 서로 다른 창을 보여 주세요. 복제/미러링은 두 화면에 같은 바탕화면을 표시합니다. 원래 슬라이드 창을 청중용 화면으로 옮긴 뒤 그 창을 클릭하고 **F**를 눌러 전체 화면으로 만듭니다.

화상 회의에서는 회의 앱의 공유 미리보기를 보거나 동료에게 슬라이드만 보이는지 확인받으세요. 바탕화면 전체를 공유하면 발표자 창을 앞으로 가져올 때 노트도 보일 수 있습니다.

### 4. 두 창이 함께 움직이는지 확인하고 시작점으로 돌아가기 {#check-sync}

Presenter View에서 노트 편집란 밖의 제목 영역을 클릭한 뒤 **오른쪽**을 누릅니다. 청중 창에서도 같은 슬라이드 또는 같은 표시 단계로 넘어가는지 확인하세요. **왼쪽**으로 되돌립니다. 이후 슬라이드 창에서 **Home**을 누르거나 세션 목차, 검색, 사이드바에서 찾아 예정한 시작 슬라이드로 돌아갑니다.

발표 전에 불필요하게 열어 둔 덱 사본은 닫으세요. 실제 사용할 창으로 리허설합니다. 첫 장으로 돌아가는 것만으로 모든 퀴즈, 입력 위젯, 필기가 초기화되지는 않으므로 작성자가 안내한 초기화 방법을 사용하세요.

## 먼저 익힐 기본 조작 {#essential-controls}

**원래 슬라이드 창**의 빈 공간을 클릭한 뒤 아래 키를 사용합니다. 일반 알파벳 키에는 Ctrl, Command, Alt를 함께 누르지 않습니다. 입력기를 사용하던 중 알파벳 단축키가 반응하지 않으면 영문 입력으로 바꾸고 다시 시도하세요.

| 키 | 화면에서 일어나는 일 | 쓸 때 |
| --- | --- | --- |
| 오른쪽 / Space / PageDown | 다음 내용을 표시하고, 남은 표시 단계가 없으면 다음 장으로 이동 | 보통의 발표 진행 |
| 왼쪽 / PageUp | 지원되는 표시 단계를 되돌린 뒤 이전 장으로 이동 | 설명 다시 보여 주기 |
| 아래 / 위 | Canvas 단계나 탭 등 해당 슬라이드에 등록된 동작 수행. 장마다 다름 | 작성자의 조작 안내에 따라 진행 |
| N | Presenter View를 열거나 이미 열린 창으로 이동 | 발표자 노트 보기 |
| F | 전체 화면으로 전환하거나 해제 | 슬라이드만 크게 보여 주기 |
| G | 여러 슬라이드를 격자로 보여 주는 전체 보기 열기/닫기 | 슬라이드 둘러보기. 실제 이동은 검색이나 사이드바 사용 |
| S | 전체 화면이 아닐 때 썸네일 사이드바 표시/숨기기 | 썸네일을 클릭해 해당 장으로 이동 |
| Home / End | 첫 장 / 마지막 장으로 이동 | 시작 또는 마무리로 돌아가기 |
| T | 전체 라이트/다크 테마 전환 | 강의실이나 프로젝터에 맞추기. 테마가 고정된 장은 그대로 유지 |
| Escape | 현재 상태에 따라 필기 모드나 열린 보기 종료 | 일반 슬라이드 화면으로 복귀 |

**발표용 리모컨은 제품마다 보내는 키가 다를 수 있습니다.** 일반 슬라이드와 애니메이션 슬라이드에서 다음/이전 버튼을 각각 시험하세요. 장은 넘어가지만 Canvas 단계를 조작할 수 없다면 그 부분에서는 키보드의 아래/위를 사용합니다.

발표자 창에서도 탐색과 단계 표시 키를 사용할 수 있습니다. 다만 아래쪽 **Previous / Next** 버튼은 장 단위로 이동하므로 키보드의 단계별 표시를 대신하지 않습니다. 내용을 하나씩 보여 주며 설명할 때는 키보드를 쓰세요. 전체 화면, 전체 보기, 검색은 원래 슬라이드 창에서 조작합니다.

## 발표자 노트 읽고 내 말로 다듬기 {#use-speaker-notes}

| Presenter View 영역 | 사용 방법 |
| --- | --- |
| Current Slide | 단계별로 표시된 내용까지 포함해 청중이 보는 화면 확인 |
| Next Slide | 다음 장으로 연결할 말 준비. 이 미리보기 자체는 조작 대상이 아님 |
| Speaker Notes | 작성자가 준비한 설명, 예시, 질문, 진행 지시 읽기 |
| Target | 작성자가 입력한 해당 슬라이드의 예정 시간. 있을 때만 표시 |
| 상단 타이머 | 현재 페이지 세션에서 Presenter View를 처음 연 뒤의 경과 시간. 슬라이드별 카운트다운이 아님 |
| 패널 사이 구분선 | 끌어서 노트나 현재 슬라이드 영역을 넓히기 |

리허설 전에 노트를 읽으세요. **핵심 설명 → 청중에게 질문 → 슬라이드 조작 → 결과 설명 → 다음 장** 순서로 진행하면 좋습니다. 청중에게 답을 고르라고 말하는 중에 퀴즈 정답을 먼저 표시하지 않도록 연습하세요.

단계가 있는 슬라이드에서는 노트의 주황색 ↓ 배지가 Down 키를 누를 위치를 알려 주고, 화살표 버튼 아래의 상태 줄이 그 장에 단계가 남았는지(예: ↓ 다음 단계 있음 (지금 1/3)), 아니면 다음 키 입력으로 다음 슬라이드로 넘어가는지 알려 줍니다. 자세한 내용은 [단계 안내와 아래 화살표 표시](../remarp-guide/keyboard-shortcuts.md#step-cue)를 참고하세요.

요약만 보인다면 노트 영역 안에서 스크롤해 아래 설명까지 읽으세요. 가로 구분선을 위로 끌어 노트 영역을 더 넓힐 수도 있습니다.

본인에게 맞는 표현으로 바꾸려면 다음과 같이 합니다.

1. **Edit notes**를 누르거나 노트를 더블클릭합니다.
2. 내용을 수정합니다.
3. **Save notes** 또는 **Ctrl+Enter / Command+Enter**로 저장합니다. 편집 중 Escape는 취소이며, 편집란을 벗어나도 저장됩니다.
4. 발표 키를 누르기 전에 편집란 밖을 클릭합니다. 편집 중 방향키는 글자 입력란 안에서 동작합니다.

**Edited**는 로컬 수정 표시입니다. **Reset to original**은 그 장의 노트를 작성자 원본으로 되돌립니다. 수정은 해당 브라우저에 저장되며 작성자의 원본, 다른 컴퓨터, 내보낸 PowerPoint에는 반영되지 않습니다. 공통 자료에 남겨야 할 문장은 작성자에게 전달하세요. 노트 문장을 수정해도 원본의 진행 표시와 예정 시간은 그대로 유지됩니다.

리허설 때 Presenter View를 열면 타이머도 그때 시작됩니다. 공식 세션 시작 시간으로 간주하지 말고 필요하면 별도 시계를 사용하세요. 현재 발표자 도구 모음에는 타이머 초기화 버튼이 없습니다.

## 인터랙티브 슬라이드 진행하기 {#operate-interactive-slides}

먼저 펜이나 돋보기 모드를 꺼서 클릭이 슬라이드에 전달되게 하세요. 아래 조작은 작성자가 해당 상호작용을 넣은 경우에 사용합니다.

### 글자가 단계별로 나타나는 장 {#stepwise-text}

**오른쪽** 또는 **Space**를 한 번 누르고 새로 나타난 내용을 설명한 뒤 다시 누릅니다. 내용이 나타나는 동안 슬라이드 번호는 그대로입니다. 지원되는 표시 단계는 **왼쪽**으로 되돌릴 수 있습니다. 마지막 내용까지 표시한 뒤 다음 진행 키를 누르면 다음 장으로 넘어갑니다.

### 흐름 애니메이션과 Canvas 다이어그램 {#canvas-flows}

표준 단계 제어 Canvas 슬라이드는 **아래**로 진행하고 **위**로 되돌립니다. 무엇이 움직이거나 나타났고 어떻게 바뀌었는지 설명한 다음 진행하세요. 슬라이드에 재생, 일시 정지, 초기화 버튼이 따로 있다면 작성자의 진행표에 적힌 조작을 사용합니다.

키를 길게 누르지 마세요. 설명 단계를 한꺼번에 넘기거나 다음 장으로 이동할 수 있습니다. 마지막 단계에서 어떻게 동작하는지 리허설 때 확인합니다. 움직이는 그림이라고 모두 자동 재생되는 것은 아닙니다.

### 탭과 비교 화면 {#tabs-and-comparisons}

탭이나 비교 컨트롤을 클릭하고 선택된 대안을 설명한 다음 다른 항목으로 바꿉니다. 표준 탭은 **아래 / 위**로도 순환합니다. 탭을 바꾸는 것과 슬라이드를 넘기는 것은 다릅니다.

두 설계를 비교한다면 먼저 “어느 구성 요소가 기다리는지 보세요”처럼 볼 지점을 알려 주세요. 차이를 설명하지 않고 빠르게 전환하면 청중이 따라가기 어렵습니다.

### 퀴즈 {#quizzes}

1. 문제를 읽고 청중이 고를 시간을 줍니다.
2. 구두로 답을 받거나 사용 중인 회의 도구로 의견을 받습니다.
3. 슬라이드 창에서 선택한 답을 클릭합니다.
4. 표시된 피드백을 읽고 작성자가 준비한 해설로 설명합니다.

슬라이드의 클릭은 현재 화면에서 보여 주는 시연이며 청중 전체의 답을 모으는 투표 시스템은 아닙니다. 재시도와 초기화 동작은 작성된 퀴즈에 따라 다릅니다. 발표 전에 정답과 다시 진행하는 방법을 확인하세요. 다른 장에 갔다 오는 것만으로 선택이 지워진다고 가정하지 않습니다.

### 슬라이더, 시뮬레이션, 계산기 {#input-widgets}

바꿀 입력과 예상 결과를 먼저 말합니다. 슬라이더 하나를 움직이거나 입력값 하나를 바꾼 뒤, 결과값과 그 값이 변한 이유를 설명하세요. 화면에 **Reset**이 있으면 준비한 예제로 되돌리는 데 사용합니다.

입력 조작 뒤에는 슬라이드의 빈 공간을 클릭하고 탐색 키를 누릅니다. 초기화 버튼이 없는 장도 있으므로 작성자가 시작값과 복구 방법을 제공해야 합니다. 페이지 새로고침이 모든 상태를 초기화하는 것은 아니며, 저장되지 않은 필기가 사라질 수 있습니다.

### 용어 설명과 탐색형 아키텍처 다이어그램 {#details-and-diagrams}

강조된 용어에 마우스를 올리거나 키보드 포커스를 두면 짧은 설명이 나오고, 클릭하면 상세 패널이 열릴 수 있습니다. 설명이 끝나면 패널의 닫기 버튼을 누릅니다. 작성자가 조작 요소로 만든 용어만 이렇게 동작합니다.

Archify 다이어그램은 슬라이드 안에 들어 있는 별도의 인터랙티브 페이지입니다. 표시된 컨트롤로 경로를 탐색하거나 확대하세요. 안쪽을 클릭한 뒤에는 다이어그램 바깥의 슬라이드 영역을 클릭해 키보드 입력을 발표 화면으로 돌려줍니다. 그렇지 않으면 방향키가 슬라이드에 전달되지 않을 수 있습니다.

슬라이더, 퀴즈, 삽입된 다이어그램 등이 발표자 미리보기에서 반응하지 않으면 원래 슬라이드 창에서 조작하세요. 미리보기는 지원되는 클릭을 전달하지만 모든 위젯이 독립적으로 실행되는 두 번째 화면은 아닙니다.

## 가리키기, 필기, 확대하기 {#point-and-draw}

설명할 때 선택적으로 쓰는 도구입니다. 발표에서 사용하기 전에 한 번씩 연습하세요.

| 키 | 동작 |
| --- | --- |
| P | 레이저 켜기. 이미 레이저 모드라면 다시 눌러 필기 모드 끄기 |
| O | 현재 페이지 세션 동안 남는 펜 켜기 |
| I | 형광펜 켜기 |
| U | 획 단위 지우개 켜기 |
| Y | 돋보기 켜기. 확대할 곳으로 마우스 이동 |
| C | 현재 슬라이드의 모든 필기 지우기 |
| 1 / 2 / 3 | 얇게 / 보통 / 굵게. 돋보기 모드에서는 2배 / 3배 / 4배 |
| Escape | 키가 페이지에 전달되는 환경에서 필기 모드 끄기 |

필기 도구를 켠 상태에서 마우스를 끌어 그립니다. 레이저 자국은 기본적으로 3초 뒤 사라지고, 펜과 형광펜은 현재 페이지 세션 동안 남습니다. 발표자 미리보기와 청중 창에 같은 필기가 표시됩니다. 덱 파일에 저장되는 것은 아니며 페이지를 새로고침하면 사라집니다.

**퀴즈, 탭, 다이어그램을 클릭하기 전에 필기 모드를 끄세요.** 펜, 형광펜, 지우개, 돋보기 상태에서는 P를 두 번 누릅니다. 첫 번째는 레이저로 바꾸고 두 번째는 필기 모드를 끕니다. 이미 레이저라면 P 한 번이면 됩니다. 펜을 레이저로 바꾸기만 해서는 슬라이드 클릭이 복구되지 않습니다.

전체 화면에서는 브라우저와 입력 위치에 따라 Escape 동작이 다릅니다. 종료되지 않으면 슬라이드의 빈 공간을 클릭하고 다시 누르거나, Escape를 길게 누르거나, 브라우저의 전체 화면 종료 기능을 사용하세요. 색상 선택과 브라우저별 세부 동작은 [키보드 레퍼런스](/docs/remarp-guide/keyboard-shortcuts)를 참고합니다.

## 원하는 장 찾기와 생략하기 {#find-or-skip}

- **검색:** 전체 보기가 열려 있으면 먼저 닫습니다. 검색 기능이 있는 덱에서는 **Ctrl+K / Command+K**, 또는 입력란 밖에서 **/** 키를 누릅니다. 제목이나 문구를 입력하고 아래/위로 결과를 고른 뒤 Enter로 이동합니다. Escape로 검색을 닫습니다.
- **사이드바:** 전체 보기가 열려 있으면 먼저 **G**로 닫습니다. 원래 슬라이드 창에서 **F**로 전체 화면을 해제합니다. 썸네일 사이드바가 안 보이면 **S**를 누른 뒤 필요한 장의 썸네일을 클릭합니다.
- **전체 보기:** **G**로 슬라이드 격자를 열거나 닫습니다. 현재 버전에서는 격자의 썸네일을 선택해도 해당 장으로 이동하지 않을 수 있으므로, 실제 이동에는 검색이나 사이드바를 사용하세요.
- **H** 또는 Presenter View의 **Hide slide**는 현재 장을 일반적인 다음/이전 진행에서 건너뛸지 전환합니다. 숨긴 장도 전체 보기에 표시되고 검색이나 사이드바로 이동할 수 있으며 삭제된 것은 아닙니다.

숨김 선택은 이 브라우저에 남습니다. 예상과 달리 한 장이 빠지면 검색이나 사이드바로 찾아 H를 다시 누르거나 사이드바의 눈 모양 컨트롤을 사용하세요. 발표 중 모르는 내용을 즉석에서 숨기기보다는 생략할 장을 작성자와 미리 정합니다.

## 청중이 들어오기 전에 한 번 리허설하기 {#rehearsal}

내용을 연습하는 시간과 별개로, 아래 조작 확인에 약 5분을 잡으세요. 실제 발표할 컴퓨터, 브라우저, 화면 공유 구성에서 진행합니다.

1. 받은 링크를 열고 세션과 시작 슬라이드를 확인합니다.
2. N으로 Presenter View를 엽니다. 노트가 잘 읽히고 청중 공유에는 나오지 않는지 확인합니다.
3. 텍스트 표시 단계와 Canvas 단계가 있다면 각각 한 단계 진행했다가 되돌립니다.
4. 진행표에 있는 탭, 퀴즈 답, 입력 위젯을 하나씩 조작합니다. 작성자의 안내에 따라 시작 상태로 복구합니다.
5. P로 레이저를 켜서 표시한 뒤 끄고, 일반 슬라이드 컨트롤이 다시 클릭되는지 확인합니다.
6. 검색이나 사이드바로 한 장을 찾아갔다가 시작점으로 돌아옵니다. 숨긴 장도 확인합니다.
7. 정적인 백업 파일을 열고 문제가 생겼을 때 어떻게 전환할지 확인합니다.

빠진 조작 안내가 있다면 발표 전에 작성자에게 보완을 요청하세요. 단축키를 아는 것과 각 단계에서 무슨 말을 할지 아는 것은 별개의 준비입니다.

## 발표 중 막혔을 때 {#recover-during-a-talk}

| 상황 | 바로 해 볼 것 |
| --- | --- |
| N을 눌러도 노트가 안 열림 | 슬라이드 배경을 클릭하고 필요하면 영문 입력으로 바꾼 뒤 사이트 팝업을 허용합니다. 다른 창 뒤에 이미 열렸는지도 확인합니다 |
| 청중에게 노트가 보임 | 공유를 멈추고 원래 슬라이드 창이나 탭을 선택한 뒤 회의 미리보기로 확인하고 다시 진행합니다 |
| 오른쪽을 눌렀는데 장 번호가 그대로임 | 현재 장의 단계 표시를 마칩니다. 설명 한 번에 키를 한 번씩 누릅니다 |
| 방향키가 먹지 않는 것 같음 | 노트나 입력란 편집을 끝내고 검색을 닫거나 다이어그램 밖을 클릭한 뒤 슬라이드 배경을 클릭합니다 |
| 퀴즈나 탭이 눌리지 않음 | 펜/돋보기 모드를 끕니다. 원래 슬라이드 창에서도 조작해 봅니다 |
| 특정 장을 건너뜀 | 검색이나 사이드바로 찾아 H 또는 눈 모양 컨트롤에서 숨김 상태를 확인합니다 |
| 발표자 창과 슬라이드가 서로 다름 | 불필요한 사본을 닫습니다. 사용할 원래 슬라이드 창을 열어 둔 채 N으로 그 창의 발표자 보기를 다시 엽니다 |
| 발표자 창에서 F가 동작하지 않음 | 원래 슬라이드 창을 클릭하고 F를 누릅니다 |
| 이미지나 아키텍처 그림이 없음 | 연결과 작성자의 열기 안내를 확인합니다. 빨리 복구되지 않으면 정적인 백업 자료를 사용합니다 |
| 전체 화면에서 나올 수 없음 | 입력란/다이어그램 밖을 클릭한 뒤 Escape 또는 브라우저의 전체 화면 종료 기능을 사용합니다 |
| 퀴즈나 슬라이더에 리허설 상태가 남아 있음 | 안내된 초기화나 시작값을 사용합니다. 안내가 없으면 작성자에게 확인합니다 |

PDF나 PowerPoint로 전환했다면 상호작용 부분을 말로 설명하며 이어갑니다. 스크린샷 기반 사본에서는 탭, 퀴즈, 슬라이더가 동작하지 않습니다. 백업은 미리 확인하세요. 브라우저 PDF 내보내기는 Canvas를 플레이스홀더로 바꿀 수 있습니다.

## 작성자: 슬라이드와 함께 전달할 안내 {#author-handoff}

덱 링크를 보낼 때 **이 안내도 함께** 보내세요. 발표자가 플러그인 제작 문서를 찾아다니지 않고 확인할 수 있어야 합니다. 아래 문구를 복사하고 대괄호 안을 모두 실제 값으로 바꿔 전달합니다.

> 발표하실 슬라이드를 전달드립니다.
>
> 발표 자료: [발표 URL]\
> 발표 조작 안내: [이 발표자 가이드의 URL]\
> 청중과 사전 지식: [청중]\
> 발표 시간, 세션, 시작 장: [시간 / 세션 / 슬라이드 제목]\
> 꼭 전달할 핵심 내용: [두세 가지]\
> 검증한 브라우저와 변경한 조작: [브라우저 / 변경 내용 또는 기본값]\
> 선택하거나 생략할 장: [제목 또는 없음]\
> 인터랙티브 장의 진행표와 퀴즈 해설: [문서 또는 노트 위치]\
> 인터넷이 필요한 부분과 대안: [데모 / 대체 설명 또는 없음]\
> 확인한 정적 백업: [PDF 또는 PowerPoint URL]\
> 내용 질문이나 문제 발생 시: [연락처]

진행표는 다음처럼 작성하되 예시 제목과 조작을 실제 덱의 내용으로 바꿉니다.

| 슬라이드 제목 / 번호 | 설명하거나 질문할 말 | 조작 | 보여야 하는 결과 / 복구 | 시간 |
| --- | --- | --- | --- | --- |
| 요청 흐름 / [번호] | 저장 버튼을 누르면 무슨 일이 생기는지 질문 | 오른쪽을 한 번씩 눌러 텍스트 세 단계 표시 | 클라이언트 → 작업자 → 결과. 왼쪽으로 표시 되돌리기 | 3분 |
| 아키텍처 / [번호] | 요청 하나가 들어와 끝나는 경로 설명 | [실제 다이어그램 컨트롤과 클릭 순서] | [강조되는 경로와 처음 화면으로 복구하는 방법] | 4분 |
| 이해도 확인 / [번호] | 누가 요청을 시작하는지 질문 | 답을 기다린 뒤 [정답 보기] 클릭 | [피드백, 해설, 검증한 재시도/초기화 방법] | 2분 |

각 장의 발표자 노트에는 **핵심 메시지, 실제로 할 설명, 조작 시점, 화면에서 바뀔 내용, 시간, 다음 장으로 이어지는 말**을 담으세요. 예시 숫자는 예시라고 표시하고 사실 주장에는 출처나 한계를 남깁니다. 발표자가 완성된 그림만 보고 애니메이션 순서를 추측하게 해서는 안 됩니다.

발표자 창은 청중 화면에 노트가 표시되지 않게 하는 기능이지 접근 통제가 아닙니다. 배포된 HTML에는 원본 노트가 포함될 수 있습니다. 공유 전에 비공개 정보를 제거하고, 다음 발표자에게 필요한 리허설 중 수정은 유지보수하는 원본에도 반영하세요.

제작, 다시 빌드하기, 내보내기 절차는 [작성자 가이드](./skills/reactive-presentation.md)에서 확인합니다.
