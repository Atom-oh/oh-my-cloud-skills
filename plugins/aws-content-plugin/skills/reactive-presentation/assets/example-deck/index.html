워크로드 유형별 배치 전략

NodePool 선택 기준

general-purpose
기본 NodePool — On-Demand, 다양한 인스턴스 패밀리
별도 설정 없이 바로 스케줄링, 통합(consolidation)으로 유휴 노드 자동 회수
PDB 필수
21일 노드 교체 주기를 무중단으로 흡수
minAvailable + topologySpreadConstraints로 한 노드 교체가 한 replica만 건드리게
핵심 규칙 — 웹 서비스는 기본 풀로 충분하지만, PDB 없는 Deployment는 교체 주기마다 순단이 사용자에게 전달됩니다.
커스텀 NodePool + Spot
capacityType: spot — 중단 허용 워크로드에 최대 90% 절감
Spot 회수 2분 통지는 컨트롤러가 처리 — Job은 재시도(backoffLimit)만 챙기면 됨
taint 분리
batch 전용 taint로 웹 워크로드 유입 차단
Job 쪽에는 toleration + nodeSelector를 함께 걸어 풀 밖으로 새지 않게
핵심 규칙 — Spot은 반드시 별도 NodePool로 분리하고, 체크포인트가 없는 긴 작업은 On-Demand 풀에 남겨 두세요.
system NodePool
CriticalAddonsOnly taint — 애드온 전용 격리
CoreDNS·metrics-server 같은 클러스터 필수 컴포넌트가 여기에 배치됨
과점유 주의
시스템 풀에 일반 워크로드 tolerate 금지
tolerations: operator: Exists 같은 광범위 설정이 가장 흔한 유입 경로
핵심 규칙 — 시스템 풀은 건드리지 않습니다. 일반 워크로드의 tolerations를 admission 정책(Kyverno 등)으로 검사하세요.

커스텀 풀은 다섯 줄이면 된다

Spot 배치 풀 NodePool 예시

nodepool-batch.yaml
apiVersion: karpenter.sh/v1
kind: NodePool
metadata:
  name: batch-spot
spec:
  template:
    spec:
      requirements:
        - key: karpenter.sh/capacity-type
          operator: In
          values: ["spot"]  # 중단 허용 워크로드 전용
      taints:
        - key: workload/batch
          effect: NoSchedule
  disruption:
    consolidationPolicy: WhenEmptyOrUnderutilized

전환 전 다섯 가지 점검

클릭해서 체크

  • 모든 Deployment에 PDB가 있는가 — 21일 교체 주기 무중단 흡수
  • 커스텀 AMI·userData 의존이 없는가 — 있다면 DaemonSet/사이드카로 이전
  • 노드 SSH에 의존하는 디버깅 runbook이 없는가
  • Spot 전용 NodePool과 taint 설계가 준비됐는가
  • 비용 태그 전략 — NodePool 단위 라벨로 Cost Explorer 분리
